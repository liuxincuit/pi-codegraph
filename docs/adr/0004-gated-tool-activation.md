# 工具可用性由索引、配置与路径发现共同决定

v0.1.3 及以前，只要 CLI 存在，`codegraph_explore` 在**每个**会话都被声明给模型——包括工作目录没有索引、工具必然失败的会话。同时，会话只能看到工作目录自己的索引：在 `/a` 启动的会话不知道 `/b` 已建索引，尽管工具本来就支持 `path` 参数。

决策分两部分。

## 1. 注册与声明分离，可用性由 gate 判定

所有 codegraph 工具都以 `defaultActive: false` 注册：注册不等于声明给模型，活动集由 `setToolsEnabled()` 按 gate 重算（这是 pi 官方推荐的动态工具暴露模式，`defaultActive` 自 pi 0.99 起提供）。

gate 为真当且仅当满足其一：

- 工作目录存在 `.codegraph/codegraph.db`（与状态栏判据一致）；
- 配置 `inject` 为 `"always"`（`inject` 默认为 `"auto"`）；
- 本会话的路径发现命中过某个索引目录（见下）。

gate 为假时：工具不出现在系统提示中，也不注入任何 codegraph 提示——延续 ADR-0003 的原则，绝不宣传调不到的工具。`/codegraph-init` 成功建好索引后会重算 gate 并补注入索引提示，否则新索引要等下次会话才可用。

## 2. 路径发现：探索到索引目录就提示并启用

工具结果里带路径时（`read`/`edit`/`write`/`ls`/`grep`/`find` 与 codegraph 工具自身的 `path`，`codegraph_files` 的 `dir`），从该路径（是文件则取父目录）逐级向上查找最近的 `.codegraph/codegraph.db`，最多 10 层。命中一个此前未见过的索引根时：

1. 把 `<system-reminder>` 追加到该工具结果，告知"该目录有索引、用 `codegraph_explore(query=…, path=…)` 查询"；
2. 若工具尚未声明给模型（gate 为假），顺带启用——`setActiveTools` 在下一个 turn 生效，而模型正是在下一个 turn 才读到这条注入，两者对齐；
3. 通过 `ctx.ui.notify` 提示用户（TUI 与 RPC 都可见）。

每个索引根每会话只提示一次（`discoveredRoots`），目录查找结果缓存到会话结束（`indexRootCache`），`session_start` 清空。

## 备选方案与否决理由

- **无条件声明工具**（v0.1.3 行为）：未索引项目里工具必失败，噪声与误调用换不来任何收益。
- **发现时只注入提示、不启用工具**：会宣传调不到的工具，直接违反 ADR-0003。除非用户配置了 `inject: "always"`，否则"发现"与"可用性"必须一起变化。
- **解析 `bash` 命令字符串里的路径**：脆弱且易误判（重定向、变量、引号）；`bash` 工具本身没有路径参数，故不触发发现。已知缺口，等有真实需求再补。
- **发现后自动 `codegraph sync` 该目录**：与 ADR-0002 的精神冲突——索引的建立与更新是用户的决定，不是探索的副作用。
- **每个会话都向上寻找工作目录以外的索引**（不必等工具触摸路径）：需要扫描或猜目录，代价高且容易在 `$HOME` 这类位置误命中。

## 后果

- 中途改变声明给模型的工具集会改变请求前缀。对无法表达工具集变更的 provider，pi 会发送完整 transcript checkpoint（前缀缓存失效）。次数受限于每会话发现的索引根数量，且只发生在真正跨项目探索的会话里。
- 技能注入（`resources_discover`）跟随同一个 gate：gate 为假时不宣传 codegraph 技能。发现式启用之后没有技能指引，但注入的发现提示本身自包含（工具名、`path` 用法、何时该用）。
- pi < 0.99 没有 `defaultActive`，该字段被忽略，工具退化为"注册即声明"（旧行为），不会报错。
- 负结果的目录缓存意味着：会话中途**新建**的索引目录，要等到下次会话才会被 gate 与提示识别（`/codegraph-init` 成功路径例外，它显式刷新）。
